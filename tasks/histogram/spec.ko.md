# 과제: 정수 히스토그램 (정확한 빈 개수)

> 이 문서는 `spec.md`(모델에 그대로 들어가는 영어 명세)의 한국어 번역이며 사람이 읽기 위한 것이다. 모델에는 보내지 않는다. 두 문서가 다르면 `spec.md`가 기준이다.

## 정의

정수 배열 `data`의 원소 중 각 빈 b와 같은 값을 가진 원소의 개수를 세어 출력 배열 `hist`에 저장하는 `histogram` 이라는 이름의 함수를 구현한다.

    hist[b] = 0 ≤ i < n 이면서 data[i] == b 인 인덱스 i 의 개수,    0 ≤ b < nbins

`data`의 모든 원소는 정확히 하나의 빈에 속하므로 개수의 합은 n 이다. 어떤 원소도 속하지 않는 빈의 개수는 0 이다.

## 데이터 배치

- `data`는 n개의 부호 있는 32비트 정수(int32) 배열이며 연속이다. 모든 값은 0 ≤ data[i] < nbins 를 만족한다. 이는 호출자가 보장한다: 빈 범위 밖의 원소는 없으므로 범위 검사는 필요 없다.
- `hist`는 정확히 nbins개의 부호 있는 32비트 정수(int32) 배열이며 연속이다.
- 이 범위 밖을 읽거나 쓰지 않는다.
- `data`와 `hist`의 시작 주소는 64바이트 정렬되어 있다. 두 버퍼는 서로 겹치지 않는다.
- n과 nbins는 양의 정수이며 항상 `data`와 `hist`의 실제 크기와 일치한다. n은 부호 있는 32비트 정수에 들어가므로 모든 개수도 부호 있는 32비트 정수에 들어간다.

## 계약

- 함수의 매개변수는 정확히 네 개이며 순서는 data, hist, n, nbins 다. 매개변수를 추가·제거·개명·재배열할 수 없다. 기본값이 있는 매개변수의 추가도 금지다. 정확한 선언은 이 명세와 함께 주어지는 언어별 지시에 있다.
- hist는 호출자가 할당한다. hist의 초기 내용은 임의의 값(미정의 유한값이며 0이 아니다)이고 사용해서는 안 된다. 함수는 개수가 0인 빈을 포함해 hist의 **모든** 원소를 써야 한다. 세기 전에 빈을 0으로 만드는 것은 함수의 책임이다. 호출 전 hist에 있던 값에 더하거나 다른 방식으로 결합해서는 안 된다.
- 결과는 반드시 hist에 써야 한다. 함수의 반환값은 무시된다. 결과는 오직 버퍼 hist에서만 읽으므로, hist를 채우지 않고 새 배열을 반환하는 것은 hist를 쓰지 않은 것으로 간주된다.
- `data`는 읽기 전용이다. 일시적으로라도 수정해서는 안 된다(예: `data`를 제자리 정렬하면 안 된다).
- 함수 안에서 임시 메모리(작업 버퍼)를 할당할 수 있으나 반환 전에 해제해야 한다.
- 함수는 파일을 읽거나 쓰지 않고, 네트워크를 쓰지 않고, 표준 출력·표준 오류에 아무것도 출력하지 않고, 환경변수를 읽거나 바꾸지 않고, 전역·정적 가변 상태에 의존하거나 이를 변경하지 않는다. 호출 사이에 상태를 유지하지 않는다.
- 함수는 같은 프로세스에서 같은 버퍼 또는 다른 버퍼로 여러 번 호출된다. 모든 호출은 단독으로 완전하고 올바른 결과를 내야 하며, 같은 입력에 대한 두 호출의 결과는 동일해야 한다.
- 함수는 모든 양의 n과 nbins에 대해 올바라야 한다. nbins = 1, nbins보다 작은 n, 2·4·8·16 또는 그 밖의 어떤 블록 크기의 배수도 아닌 n·nbins를 포함한다.
- 평가에서 `data`의 값은 정수 0, 1, …, nbins − 1 에서 독립적으로 균등하게 뽑는다. 따라서 각 빈은 약 n / nbins 개의 원소를 받고 연속한 원소 사이에는 아무 관계가 없다.

## 정확도

세기는 정확한 정수 연산이므로 허용오차가 없다. 출력은 같은 입력으로 계산한 참조 개수와 원소별로 비교하며, 모든 0 ≤ b < nbins 에 대해

    hist[b] == ref[b]

일 때만 통과한다. 참조와 어떤 크기로든 다른 빈(하나 차이 포함)은 실패다.

## 평가

- 정확성 형태 (n, nbins): (13, 4), (100,003, 37), (1,048,576, 256).
- 성능 형태 (n, nbins): (33,554,432, 1024). 성능 형태의 출력도 정확 일치 검사를 통과해야 한다.
- 절차: 정확성 형태마다 입력의 새 복사본으로 함수를 두 번 호출하며, 매 호출 전에 hist를 0이 아닌 임의의 값으로 채운다. 각 출력은 참조와 정확히 같아야 하고 두 출력은 서로 동일해야 한다. 버퍼 밖 쓰기와 입력의 변조는 탐지되며 실패로 간주된다.
- 모든 정확성 검사를 통과하면 성능 형태에서 시간을 잰다: 워밍업 호출 3회 뒤 계측 호출 10회, 계측 호출의 중앙값이 보고되는 실행 시간이다. 함수 호출 시점에 입력은 이미 메모리에 있으며, 측정 시간은 호출 자체의 소요 시간이다.
- 평가에 쓰는 하드웨어·스레드 수·빌드 설정은 언어별 지시에 명시되어 있다.

## 목표

위 규칙을 모두 지키면서 성능 형태에서 가능한 한 가장 빠른 올바른 구현을 제시하라. 모든 형태에서의 정확성이 속도보다 우선한다. 정확성 검사 중 하나라도 실패한 구현은 성능 결과를 받지 못한다.
