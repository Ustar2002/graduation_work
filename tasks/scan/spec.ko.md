# 과제: 32비트 정수의 inclusive 접두합(스캔)

> 이 문서는 `spec.md`(모델에 그대로 들어가는 영어 명세)의 한국어 번역이며 사람이 읽기 위한 것이다. 모델에는 보내지 않는다. 두 문서가 다르면 `spec.md`가 기준이다.

## 정의

길이 n인 정수 배열 x의 inclusive 접두합을 계산해 같은 길이의 출력 배열 `out`에 저장하는 `scan` 이라는 이름의 함수를 구현한다.

    out[i] = Σ_{k=0}^{i} x[k],    0 ≤ i < n

즉 out[0] = x[0], out[1] = x[0] + x[1], … 이고 out[n−1]은 x의 모든 원소의 합이다.

## 데이터 배치

- `x`와 `out`은 부호 있는 32비트 정수(2의 보수, int32) n개의 배열이며 연속이고 원소 사이에 패딩이 없다.
- `x`는 정확히 n개, `out`은 정확히 n개의 원소를 가진다. 이 범위 밖을 읽거나 쓰지 않는다.
- `x`와 `out`의 시작 주소는 64바이트 정렬되어 있다. 두 버퍼는 서로 겹치지 않는다.
- n은 양의 정수이며 항상 `x`와 `out`의 실제 크기와 일치한다.

## 계약

- 함수의 매개변수는 정확히 세 개이며 순서는 x, out, n 이다. 매개변수를 추가·제거·개명·재배열할 수 없다. 기본값이 있는 매개변수의 추가도 금지다. 정확한 선언은 이 명세와 함께 주어지는 언어별 지시에 있다.
- out은 호출자가 할당한다. out의 초기 내용은 미정의(임의의 값이며 0이 아니다)이고 사용해서는 안 된다. 함수는 out의 **모든** 원소를 올바른 결과로 덮어써야 한다. 호출 전 out에 있던 값에 더하거나 다른 방식으로 결합해서는 안 되며, out이 0으로 초기화되어 있다고 가정해서도 안 된다.
- 결과는 반드시 out에 써야 한다. 함수의 반환값은 무시된다. 결과는 오직 버퍼 out에서만 읽으므로, out을 채우지 않고 새 배열을 반환하는 것은 out을 쓰지 않은 것으로 간주된다.
- `x`는 읽기 전용이다. 일시적으로라도 수정해서는 안 된다.
- 함수 안에서 임시 메모리(작업 버퍼)를 할당할 수 있으나 반환 전에 해제해야 한다.
- 함수는 파일을 읽거나 쓰지 않고, 네트워크를 쓰지 않고, 표준 출력·표준 오류에 아무것도 출력하지 않고, 환경변수를 읽거나 바꾸지 않고, 전역·정적 가변 상태에 의존하거나 이를 변경하지 않는다. 호출 사이에 상태를 유지하지 않는다.
- 함수는 같은 프로세스에서 같은 버퍼 또는 다른 버퍼로 여러 번 호출된다. 모든 호출은 단독으로 완전하고 올바른 결과를 내야 하며, 같은 입력에 대한 두 호출의 결과는 동일해야 한다.
- 함수는 모든 양의 n에 대해 올바라야 한다. n = 1, 아주 작은 n, 그리고 2·4·8·16·스레드 수 또는 그 밖의 어떤 블록 크기의 배수도 아닌 n을 포함한다.
- 입력값은 음이 아니고 작다: x의 모든 원소는 0 이상 31 이하의 정수다(평가에서는 그 범위의 균등분포에서 뽑는다). 따라서 모든 접두합은 최대 31·n 이며, 모든 평가 형태에서 부호 있는 32비트 정수에 들어간다(31 × 33,554,432 < 2³¹). 함수는 이를 전제로 할 수 있다: 오버플로 처리는 필요 없고 32비트 누적으로 충분하다. 더 넓은 중간 누산기를 쓰는 것은 자유다.

## 정확도

출력은 같은 입력으로 64비트 정수 연산으로 계산한 참조값과 원소별로 비교한다. 검사는 정확한 일치를 요구한다:

    out[i] == ref[i]    모든 0 ≤ i < n 에 대해

허용오차는 없다. 참조와 조금이라도 다른 원소가 있으면 실패다. 이 요구 안에서 알고리즘, 작업의 분할, 원소를 더하는 순서는 자유롭게 선택할 수 있다.

## 평가

- 정확성 형태 (n): 7, 100,003, 1,048,576.
- 성능 형태 (n): 33,554,432. 성능 형태의 출력도 정확 일치 검사를 통과해야 한다.
- 절차: 정확성 형태마다 입력의 새 복사본으로 함수를 두 번 호출하며, 매 호출 전에 out을 임의의 값으로 채운다. 각 출력은 정확 일치 검사를 통과해야 하고 두 출력은 동일해야 한다. 버퍼 밖 쓰기와 입력의 변조는 탐지되며 실패로 간주된다.
- 모든 정확성 검사를 통과하면 성능 형태에서 시간을 잰다: 워밍업 호출 3회 뒤 계측 호출 10회, 계측 호출의 중앙값이 보고되는 실행 시간이다. 함수 호출 시점에 입력은 이미 메모리에 있으며, 측정 시간은 호출 자체의 소요 시간이다.
- 평가에 쓰는 하드웨어·스레드 수·빌드 설정은 언어별 지시에 명시되어 있다.

## 목표

위 규칙을 모두 지키면서 성능 형태에서 가능한 한 가장 빠른 올바른 구현을 제시하라. 모든 형태에서의 정확성이 속도보다 우선한다. 정확성 검사 중 하나라도 실패한 구현은 성능 결과를 받지 못한다.
