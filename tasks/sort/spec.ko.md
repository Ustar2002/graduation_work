# 과제: 32비트 정수 정렬

> 이 문서는 `spec.md`(모델에 그대로 들어가는 영어 명세)의 한국어 번역이며 사람이 읽기 위한 것이다. 모델에는 보내지 않는다. 두 문서가 다르면 `spec.md`가 기준이다.

## 정의

입력 배열 `x`의 n개 정수를 오름차순(비감소 순)으로 출력 배열 `out`에 쓰는 `sort`라는 이름의 함수를 구현한다.

    out[0] ≤ out[1] ≤ … ≤ out[n−1]

여기서 `out`은 `x`의 재배열이다: 모든 값은 `x`에 나타나는 횟수만큼 정확히 그 횟수로 `out`에 나타난다.

## 데이터 배치

- `x`는 n개의 부호 있는 32비트 정수(int32) 배열이며 연속이다.
- `out`은 n개의 int32 값 배열이며 연속이다.
- 이 범위 밖을 읽거나 쓰지 않는다.
- `x`와 `out`의 시작 주소는 64바이트 정렬되어 있다. 두 버퍼는 서로 겹치지 않는다.
- n은 양의 정수이며 항상 `x`와 `out`의 실제 크기와 일치한다.

## 계약

- 함수의 매개변수는 정확히 세 개이며 순서는 x, out, n 이다. 매개변수를 추가·제거·개명·재배열할 수 없다. 기본값이 있는 매개변수의 추가도 금지다. 정확한 선언은 이 명세와 함께 주어지는 언어별 지시에 있다.
- out은 호출자가 할당한다. out의 초기 내용은 미정의(0이 아닌 임의의 값)이며 사용해서는 안 된다. 함수는 out의 **모든** 원소를 올바른 결과로 덮어써야 한다. out이 0으로 초기화되어 있다고 가정해서는 안 되며, 호출 전 out에 있던 값과 결과를 결합해서도 안 된다.
- 결과는 반드시 out에 써야 한다. 함수의 반환값은 무시된다. 결과는 오직 버퍼 out에서만 읽으므로, out을 채우지 않고 새 배열을 반환하는 것은 out을 쓰지 않은 것으로 간주된다.
- `x`는 읽기 전용이다. 일시적으로라도 수정해서는 안 된다. 특히 x를 제자리에서 정렬해서는 안 되며, 나중에 원래 순서를 복원하더라도 마찬가지다. 복사본을 정렬하거나 결과를 out에 직접 쓴다.
- 함수 안에서 임시 메모리(작업 버퍼)를 할당할 수 있으나 반환 전에 해제해야 한다.
- 함수는 파일을 읽거나 쓰지 않고, 네트워크를 쓰지 않고, 표준 출력·표준 오류에 아무것도 출력하지 않고, 환경변수를 읽거나 바꾸지 않고, 전역·정적 가변 상태에 의존하거나 이를 변경하지 않는다. 호출 사이에 상태를 유지하지 않는다.
- 함수는 같은 프로세스에서 같은 버퍼 또는 다른 버퍼로 여러 번 호출된다. 모든 호출은 단독으로 완전하고 올바른 결과를 내야 하며, 같은 입력에 대한 두 호출의 결과는 동일해야 한다.
- 함수는 모든 양의 n에 대해 올바라야 한다. 아주 작은 n(예: 1), 2의 거듭제곱이 아니거나 2·4·8·16 또는 그 밖의 어떤 블록 크기의 배수도 아닌 n, 그리고 중복 값이 있는 입력을 포함한다.
- 입력값은 음이 아니다: 모든 원소가 0 ≤ x[i] ≤ 2³¹ − 1 을 만족하므로 int32의 음이 아닌 전 범위가 나올 수 있지만 음수는 절대 나오지 않는다. 평가에서는 이 범위의 균등분포에서 독립적으로 뽑으므로 중복 값이 가능하며 큰 형태에서는 실제로 나타난다.

## 정확도

출력은 참조값 — 같은 입력을 오름차순으로 정렬한 것 — 과 원소별로 비교한다. 모든 원소가 정확히 일치할 때만 통과한다.

    out[i] == ref[i],    모든 0 ≤ i < n 에 대해

허용오차는 없다: 원소 하나만 달라도 실패다. 정수 다중집합의 오름차순 배열은 유일하므로, 순차든 병렬이든, 안정 정렬이든 아니든, 올바른 알고리즘은 모두 같은 출력을 낸다.

## 평가

- 정확성 형태 (n): 7, 100,003, 1,048,576.
- 성능 형태 (n): 10,000,000. 성능 형태의 출력도 검사를 통과해야 한다.
- 절차: 정확성 형태마다 입력의 새 복사본으로 함수를 두 번 호출하며, 매 호출 전에 out을 임의의 값으로 채운다. 각 출력은 검사를 통과해야 하고 두 출력은 동일해야 한다. 버퍼 밖 쓰기와 x의 변조는 탐지되며 실패로 간주된다.
- 모든 정확성 검사를 통과하면 성능 형태에서 시간을 잰다: 워밍업 호출 3회 뒤 계측 호출 10회, 계측 호출의 중앙값이 보고되는 실행 시간이다. 함수 호출 시점에 입력은 이미 메모리에 있으며, 측정 시간은 호출 자체의 소요 시간이다.
- 평가에 쓰는 하드웨어·스레드 수·빌드 설정은 언어별 지시에 명시되어 있다.

## 목표

위 규칙을 모두 지키면서 성능 형태에서 가능한 한 가장 빠른 올바른 구현을 제시하라. 모든 형태에서의 정확성이 속도보다 우선한다. 정확성 검사 중 하나라도 실패한 구현은 성능 결과를 받지 못한다.
