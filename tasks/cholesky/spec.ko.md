# 과제: 대칭 양정치 행렬의 Cholesky 분해 (단정밀도)

이 문서는 `spec.md`(LLM 에 그대로 들어가는 영어 원문)의 한국어 번역이다. 계약이 다르게 읽히면 영어 원문이 기준이다.

## 정의

대칭 양정치 n×n 행렬 A 의 Cholesky 인자를 계산하는 함수 `cholesky` 를 구현한다. Cholesky 인자는 대각 원소가 모두 양수인 유일한 하삼각 행렬 L 로,

    L · Lᵀ = A,    즉    A[i][j] = Σ_{k=0}^{min(i, j)} L[i][k] * L[j][k]    (모든 0 ≤ i, j < n)

를 만족한다. 결과는 n×n 출력 행렬 `L` 에 쓴다:

- j ≤ i (대각과 엄격 하삼각): L[i][j] 는 Cholesky 인자의 원소이고 L[i][i] > 0 이다;
- j > i (엄격 상삼각): L[i][j] 는 0 이어야 한다.

원소 단위로 쓰면, 모든 열 j = 0, …, n-1 에 대해

    L[j][j] = sqrt( A[j][j] - Σ_{k<j} L[j][k]^2 )
    L[i][j] = ( A[i][j] - Σ_{k<j} L[i][k] * L[j][k] ) / L[j][j]    (i > j)

이다. 결과가 위에서 정의한 인자이기만 하면 원소를 계산하는 순서는 자유다.

## 데이터 배치

- `A` 는 입력 행렬을 n * n 개의 IEEE-754 단정밀도(32비트) 부동소수(float32)로 담는다. 연속 배열이며 행우선(row-major)이다: A[i][j] 는 선형 인덱스 i*n + j 의 원소다. A 의 두 삼각이 모두 저장돼 있고 서로 같다(A 는 정확히 대칭이다: 인덱스 i*n + j 의 저장값과 j*n + i 의 저장값이 비트 단위로 같다).
- `L` 은 출력 행렬을 같은 행우선 배치의 연속한 float32 n * n 개로 담는다: L[i][j] 는 선형 인덱스 i*n + j 의 원소다. 엄격 상삼각을 포함해 n * n 개 원소 전부가 출력이다.
- 이 범위 밖을 읽거나 쓰지 않는다.
- `A` 와 `L` 의 시작 주소는 64바이트 정렬이다. 두 버퍼는 겹치지 않는다.
- n 은 양의 정수이며 항상 버퍼의 실제 크기와 일치한다.

## 입력에 대한 보장

- A 는 대칭 양정치다. 따라서 분해가 존재하고, 위의 모든 제곱근의 인자는 엄격히 양수이며 모든 나눗셈의 제수는 0 이 아니다 — 정확한 산술에서 그렇고, 단정밀도에서도 여유가 크다.
- A 는 조건이 좋다(well conditioned). 평가에서 A 는 B·Bᵀ + n·I 로 만든다. B 는 원소를 [-1, 1) 에서 균등하게 뽑은 n×n 행렬이고, 배정밀도로 계산한 뒤 float32 로 반올림한다. 그 결과 A 의 모든 고윳값은 약 n 과 2.4·n 사이에 있고(조건수 약 2.3), 대각 원소는 4n/3 에 가깝고, 비대각 원소의 크기는 sqrt(n/3) 정도이며, L 의 대각 원소는 sqrt(4n/3) 에 가깝다(n = 2,048 에서 약 52). 피벗팅·스케일링·정칙화는 필요 없다.
- 입력값은 유한한 float32 다. NaN·무한대·비정규 값의 특별 처리는 필요 없지만 출력에 NaN 이나 무한대가 있어서는 안 된다.

## 계약

- 함수의 매개변수는 정확히 세 개이고 순서는 A, L, n 이다. 매개변수를 추가·제거·개명·재배열할 수 없다(기본값이 있는 매개변수도 추가 금지). 정확한 선언은 이 명세에 딸린 언어별 지시가 준다.
- L 은 호출자가 할당한다. 초기 내용은 미정의(임의의 유한값)이며 사용해서는 안 된다: 함수는 L 의 **모든** 원소를 올바른 결과로 덮어써야 하며, 엄격 상삼각도 0 으로 써야 한다. 호출 전 L 에 있던 값에 더하거나 그 밖의 방식으로 섞어서는 안 된다.
- 결과는 L 에 써야 한다. 함수의 반환값은 무시된다: 결과는 버퍼 L 에서만 읽으므로, L 을 채우지 않고 새 배열을 반환하는 것은 L 을 쓰지 않은 것으로 간주한다.
- `A` 는 읽기 전용이다. 일시적으로라도 수정해서는 안 된다(예: A 안에서 제자리 분해를 해서는 안 된다).
- 임시 메모리(작업 버퍼; A 의 작업 복사본 포함)는 함수 안에서 할당할 수 있으나 반환 전에 해제해야 한다.
- 함수는 파일을 읽거나 쓰지 않고, 네트워크를 쓰지 않고, 표준 출력·표준 오류에 아무것도 쓰지 않고, 환경변수를 읽거나 바꾸지 않고, 전역·정적 가변 상태에 의존하거나 그것을 바꾸지 않는다. 호출 사이에 상태를 유지하지 않는다.
- 함수는 같은 프로세스에서 같은 버퍼 또는 다른 버퍼로 여러 번 호출된다. 모든 호출은 그 자체로 완전하고 올바른 결과를 내야 하며, 같은 입력의 두 호출은 아래 허용오차 안에서 일치해야 한다.
- 함수는 모든 양의 n 에 대해 올바라야 한다. n = 1(L[0][0] = sqrt(A[0][0])), 매우 작은 n, 2·4·8·16 또는 그 밖의 어떤 블록 크기의 배수도 아닌 n 을 포함한다.

## 정확도

출력은 같은 float32 입력 행렬로 64비트(배정밀도) 산술로 계산한 참조 인자와 원소별로 비교한다. n×n 행렬의 모든 원소(엄격 상삼각 포함)에 대해

    |L[i][j] - ref[i][j]| <= atol + rtol * |ref[i][j]|,    rtol = 1e-3, atol = 1e-3 × RMS(ref)

이면 통과다. 여기서 RMS(ref) 는 검사하는 형태의 참조 인자 n * n 원소 전체의 제곱평균제곱근이다(상삼각의 0 포함; 위에서 설명한 행렬에서는 모든 n 에 대해 RMS(ref) 가 약 1.15 라 atol 은 약 1.15e-3 이다). 참조는 엄격 상삼각에서 정확히 0 이므로, 그 자리의 원소는 크기가 atol 이하일 때만 통과한다. `L` 에 NaN 이나 무한대가 있으면 실패다. 이 허용오차 안에서 연산 순서, 중간값의 정밀도, 제곱근과 나눗셈을 계산하는 방식은 자유다.

## 평가

- 정확성 형태 (n): 6, 131, 512.
- 성능 형태 (n): 2,048. 성능 형태의 출력도 정확도 검사를 통과해야 한다.
- 메모리: 함수를 호출하는 프로세스는 입력·출력을 포함해 주소 공간 8 GiB 로 제한된다. 이를 넘는 할당은 호출 실패로 처리된다. n = 2,048 에서 n×n 작업 행렬 몇 개(float32 로 각 16 MiB)는 이 한도에 넉넉히 들어간다.
- 절차: 정확성 형태마다 함수를 입력의 새 복사본으로 두 번 호출하며, 매 호출 전에 L 을 임의의 값으로 채운다. 두 출력은 각각 정확도 검사를 통과해야 하고 서로 허용오차 안에서 일치해야 한다. 버퍼 밖 쓰기와 입력 수정은 탐지되어 실패로 친다.
- 모든 정확성 검사를 통과하면 성능 형태에서 시간을 잰다: 워밍업 3회 뒤 10회를 측정하고, 측정값의 중앙값을 실행 시간으로 보고한다. 함수가 호출될 때 입력은 이미 메모리에 있다. 측정 시간은 호출 자체의 길이다.
- 평가에 쓰는 하드웨어·스레드 수·빌드 설정은 언어별 지시가 밝힌다.

## 목표

위 규칙을 모두 지키면서 성능 형태에서 가능한 한 가장 빠른 올바른 구현을 제공한다. 모든 형태의 정확성이 속도보다 우선한다: 정확성 검사를 하나라도 실패한 구현은 성능 결과를 받지 못한다.
