# 과제: 단정밀도 일반 행렬곱 (GEMM)

> 이 문서는 `spec.md`(모델에 그대로 들어가는 영어 명세)의 한국어 번역이며 사람이 읽기 위한 것이다. 모델에는 보내지 않는다. 두 문서가 다르면 `spec.md`가 기준이다.

## 정의

행렬곱 C = A · B 를 계산하는 `gemm` 이라는 이름의 함수를 구현한다.

    C[i][j] = Σ_{k=0}^{K-1} A[i][k] · B[k][j],    0 ≤ i < M, 0 ≤ j < N

A는 M행 K열, B는 K행 N열, C는 M행 N열이다.

## 데이터 배치

- 세 행렬 모두 IEEE-754 단정밀도(32비트) 부동소수점(float32) 배열이다.
- 저장은 행우선(row-major)이고 연속이며 행 사이에 패딩이 없다: A[i][k]는 A의 선형 인덱스 i*K + k, B[k][j]는 B의 선형 인덱스 k*N + j, C[i][j]는 C의 선형 인덱스 i*N + j 위치의 원소다.
- A는 정확히 M*K개, B는 정확히 K*N개, C는 정확히 M*N개의 원소를 가진다. 이 범위 밖을 읽거나 쓰지 않는다.
- A, B, C의 시작 주소는 64바이트 정렬되어 있다. 세 버퍼는 서로 겹치지 않는다.
- M, N, K는 양의 정수이며 항상 버퍼의 실제 크기와 일치한다.

## 계약

- 함수의 매개변수는 정확히 여섯 개이며 순서는 A, B, C, M, N, K 다. 매개변수를 추가·제거·개명·재배열할 수 없다. 기본값이 있는 매개변수의 추가도 금지다. 정확한 선언은 이 명세와 함께 주어지는 언어별 지시에 있다.
- C는 호출자가 할당한다. C의 초기 내용은 미정의(임의의 유한값)이며 사용해서는 안 된다. 함수는 C의 **모든** 원소를 올바른 결과로 덮어써야 한다. 호출 전 C에 있던 값에 더하거나 다른 방식으로 결합해서는 안 된다.
- 결과는 반드시 C에 써야 한다. 함수의 반환값은 무시된다. 결과는 오직 버퍼 C에서만 읽으므로, C를 채우지 않고 새 배열을 반환하는 것은 C를 쓰지 않은 것으로 간주된다.
- A와 B는 읽기 전용이다. 일시적으로라도 수정해서는 안 된다.
- 함수는 모든 양의 M, N, K에 대해 올바라야 한다. 정사각이 아닌 형태, 아주 작은 형태, 2·4·8·16 또는 그 밖의 어떤 블록 크기의 배수도 아닌 차원을 포함한다.
- 함수 안에서 임시 메모리(작업 버퍼)를 할당할 수 있으나 반환 전에 해제해야 한다.
- 함수는 파일을 읽거나 쓰지 않고, 네트워크를 쓰지 않고, 표준 출력·표준 오류에 아무것도 출력하지 않고, 환경변수를 읽거나 바꾸지 않고, 전역·정적 가변 상태에 의존하거나 이를 변경하지 않는다. 호출 사이에 상태를 유지하지 않는다.
- 함수는 같은 프로세스에서 같은 버퍼 또는 다른 버퍼로 여러 번 호출된다. 모든 호출은 단독으로 완전하고 올바른 결과를 내야 하며, 같은 입력에 대한 두 호출의 결과는 아래 허용오차 안에서 일치해야 한다.
- 입력값은 크기가 적당한 유한 float32 수다(평가에서는 구간 [-1, 1)의 균등분포에서 뽑는다). NaN·무한대·비정규값의 특별 처리는 필요 없지만, 출력에 NaN이나 무한대가 있어서는 안 된다.

## 정확도

출력은 같은 입력으로 64비트(배정밀도) 누적으로 계산한 참조값과 원소별로 비교한다. 모든 원소에 대해

    |C[i][j] − ref[i][j]| ≤ atol + rtol · |ref[i][j]|,    rtol = 1e-3, atol = 1e-3

이면 통과한다. C에 NaN이나 무한대가 하나라도 있으면 실패다. 이 허용오차 안에서 누적 순서, 블록화·타일링, 중간값의 정밀도는 자유롭게 선택할 수 있다.

## 평가

- 정확성 형태 (M, N, K): (7, 5, 3), (200, 130, 312), (256, 256, 256).
- 성능 형태 (M, N, K): (1024, 1024, 1024).
- 절차: 정확성 형태마다 입력의 새 복사본으로 함수를 두 번 호출하며, 매 호출 전에 C를 임의의 값으로 채운다. 각 출력은 정확도 검사를 통과해야 하고 두 출력은 허용오차 안에서 서로 일치해야 한다. 버퍼 밖 쓰기와 A·B의 변조는 탐지되며 실패로 간주된다.
- 모든 정확성 검사를 통과하면 성능 형태에서 시간을 잰다: 워밍업 호출 3회 뒤 계측 호출 10회, 계측 호출의 중앙값이 보고되는 실행 시간이다. 함수 호출 시점에 입력은 이미 메모리에 있으며, 측정 시간은 호출 자체의 소요 시간이다.
- 평가에 쓰는 하드웨어·스레드 수·빌드 설정은 언어별 지시에 명시되어 있다.

## 목표

위 규칙을 모두 지키면서 성능 형태에서 가능한 한 가장 빠른 올바른 구현을 제시하라. 모든 형태에서의 정확성이 속도보다 우선한다. 정확성 검사 중 하나라도 실패한 구현은 성능 결과를 받지 못한다.
