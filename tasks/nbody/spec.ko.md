# 과제: 직접 합산 N체 중력 가속도 (단정밀도)

이 문서는 `spec.md`(LLM 에 그대로 들어가는 영어 원문)의 한국어 번역이다. 계약이 다르게 읽히면 영어 원문이 기준이다.

## 정의

n 개 물체 각각에 대해, 모든 물체가 그 물체에 가하는 연화(softened) 중력 가속도를 **모든 쌍을 직접 합산**해 계산하는 함수 `nbody` 를 구현한다. 물체 i 의 위치는 p_i = (pos[i][0], pos[i][1], pos[i][2]), 질량은 mass[i] 다. 0 ≤ i < n 인 모든 i 와 모든 좌표 c (0 = x, 1 = y, 2 = z) 에 대해

    acc[i][c] = Σ_{j=0}^{n-1} mass[j] * (pos[j][c] - pos[i][c]) / (r2(i, j) + EPS2)^(3/2)

    여기서 r2(i, j) = (pos[j][0] - pos[i][0])^2 + (pos[j][1] - pos[i][1])^2 + (pos[j][2] - pos[i][2])^2

이고, 연화 상수는 EPS2 = 1e-4 (즉 0.0001), 중력 상수는 G = 1 이다(추가 배율 없음). j = i 항은 분자가 0 이고 분모는 EPS2^(3/2) > 0 이므로 정확히 0 이다. 따라서 합에 포함해도, 건너뛰어도 결과는 같다.

EPS2 > 0 이므로 분모는 절대 0 이 되지 않는다. 두 물체가 같은 위치에 있어도 결과는 유한하다.

## 데이터 배치

- `pos` 는 n 개 물체의 위치를 n * 3 개의 IEEE-754 단정밀도(32비트) 부동소수(float32)로 담는다. 연속 배열이며 물체 순서다: 물체 i 의 좌표 c 는 선형 인덱스 3*i + c 의 원소다(물체 0 의 x, y, z, 그다음 물체 1 의 x, y, z, …).
- `mass` 는 n 개 질량을 연속한 float32 n 개로 담는다. mass[i] 는 물체 i 의 질량이다.
- `acc` 는 출력 가속도를 `pos` 와 같은 배치의 연속한 float32 n * 3 개로 담는다: 물체 i 의 가속도 성분 c 는 선형 인덱스 3*i + c 의 원소다.
- 이 범위 밖을 읽거나 쓰지 않는다.
- `pos`, `mass`, `acc` 의 시작 주소는 64바이트 정렬이다. 세 버퍼는 겹치지 않는다.
- n 은 양의 정수이며 항상 버퍼의 실제 크기와 일치한다.

## 계약

- 함수의 매개변수는 정확히 네 개이고 순서는 pos, mass, acc, n 이다. 매개변수를 추가·제거·개명·재배열할 수 없다(기본값이 있는 매개변수도 추가 금지). 정확한 선언은 이 명세에 딸린 언어별 지시가 준다.
- acc 는 호출자가 할당한다. 초기 내용은 미정의(임의의 유한값)이며 사용해서는 안 된다: 함수는 acc 의 **모든** 원소를 올바른 결과로 덮어써야 한다. 호출 전 acc 에 있던 값에 더하거나 그 밖의 방식으로 섞어서는 안 된다.
- 결과는 acc 에 써야 한다. 함수의 반환값은 무시된다: 결과는 버퍼 acc 에서만 읽으므로, acc 를 채우지 않고 새 배열을 반환하는 것은 acc 를 쓰지 않은 것으로 간주한다.
- `pos` 와 `mass` 는 읽기 전용이다. 일시적으로라도 수정해서는 안 된다.
- 임시 메모리(작업 버퍼)는 함수 안에서 할당할 수 있으나 반환 전에 해제해야 한다.
- 함수는 파일을 읽거나 쓰지 않고, 네트워크를 쓰지 않고, 표준 출력·표준 오류에 아무것도 쓰지 않고, 환경변수를 읽거나 바꾸지 않고, 전역·정적 가변 상태에 의존하거나 그것을 바꾸지 않는다. 호출 사이에 상태를 유지하지 않는다.
- 함수는 같은 프로세스에서 같은 버퍼 또는 다른 버퍼로 여러 번 호출된다. 모든 호출은 그 자체로 완전하고 올바른 결과를 내야 하며, 같은 입력의 두 호출은 아래 허용오차 안에서 일치해야 한다.
- 함수는 모든 양의 n 에 대해 올바라야 한다. n = 1(모든 가속도가 0), 매우 작은 n, 2·4·8·16 또는 그 밖의 어떤 블록 크기의 배수도 아닌 n 을 포함한다.
- 모든 물체에 대해 n 개 물체 전부를 합해야 한다(직접 합산). 먼 물체의 기여를 건너뛰거나 잘라내거나 묶는 근사 기법은 허용하지 않는다: 모든 쌍이 결과에 기여해야 한다.
- 입력값은 유한한 float32 다. 평가에서는 위치를 단위 정육면체 [0, 1)^3 에서, 질량을 구간 [0.5, 1.5) 에서 균등하게 뽑는다. 이 입력에서 합의 개별 항은 1 미만부터 수천까지 분포하고, 항들은 부분적으로 상쇄되며, 결과 가속도 성분의 크기는 수만까지 이른다. NaN·무한대·비정규 값의 특별 처리는 필요 없지만 출력에 NaN 이나 무한대가 있어서는 안 된다.

## 정확도

출력은 같은 입력으로 64비트(배정밀도) 산술로 모든 쌍을 직접 합산한 참조와 원소별로 비교한다. 모든 원소에 대해

    |acc[i][c] - ref[i][c]| <= atol + rtol * |ref[i][c]|,    rtol = 1e-3, atol = 1e-3 × RMS(ref)

이면 통과다. 여기서 RMS(ref) 는 검사하는 형태의 참조 가속도 성분 전체의 제곱평균제곱근이다(허용오차가 문제 크기에 따라 커진다). `acc` 에 NaN 이나 무한대가 있으면 실패다. 이 허용오차 안에서 합산 순서, 중간값의 정밀도, 거듭제곱 (r2 + EPS2)^(-3/2) 를 계산하는 방식은 자유다.

## 평가

- 정확성 형태 (n): 5, 301, 2,048.
- 성능 형태 (n): 16,384. 성능 형태의 출력도 정확도 검사를 통과해야 한다.
- 메모리: 함수를 호출하는 프로세스는 입력·출력을 포함해 주소 공간 8 GiB 로 제한된다. 이를 넘는 할당은 호출 실패로 처리된다. n = 16,384 에서 모든 쌍의 벡터를 담는 n×n 표는 이 한도에 들어가지 않는다.
- 절차: 정확성 형태마다 함수를 입력의 새 복사본으로 두 번 호출하며, 매 호출 전에 acc 를 임의의 값으로 채운다. 두 출력은 각각 정확도 검사를 통과해야 하고 서로 허용오차 안에서 일치해야 한다. 버퍼 밖 쓰기와 입력 수정은 탐지되어 실패로 친다.
- 모든 정확성 검사를 통과하면 성능 형태에서 시간을 잰다: 워밍업 3회 뒤 10회를 측정하고, 측정값의 중앙값을 실행 시간으로 보고한다. 함수가 호출될 때 입력은 이미 메모리에 있다. 측정 시간은 호출 자체의 길이다.
- 평가에 쓰는 하드웨어·스레드 수·빌드 설정은 언어별 지시가 밝힌다.

## 목표

위 규칙을 모두 지키면서 성능 형태에서 가능한 한 가장 빠른 올바른 구현을 제공한다. 모든 형태의 정확성이 속도보다 우선한다: 정확성 검사를 하나라도 실패한 구현은 성능 결과를 받지 못한다.
