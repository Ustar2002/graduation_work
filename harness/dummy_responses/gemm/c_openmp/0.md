The rows of `C` are independent, so the outer i loop is distributed over the OpenMP threads with a static schedule (equal contiguous chunks, no scheduling overhead). Inside, the i-k-j order keeps the innermost loop contiguous over `B` and `C`, which lets the compiler vectorize it with AVX2/FMA; `restrict` guarantees the buffers do not alias. Each row of `C` is zeroed before accumulation so its initial contents are ignored.

```c
#include <stddef.h>

void gemm(const float *restrict A, const float *restrict B, float *restrict C, int M, int N, int K)
{
    #pragma omp parallel for schedule(static)
    for (int i = 0; i < M; i++) {
        float *Ci = C + (size_t)i * N;
        for (int j = 0; j < N; j++)
            Ci[j] = 0.0f;
        for (int k = 0; k < K; k++) {
            const float a = A[(size_t)i * K + k];
            const float *Bk = B + (size_t)k * N;
            for (int j = 0; j < N; j++)
                Ci[j] += a * Bk[j];
        }
    }
}
```
